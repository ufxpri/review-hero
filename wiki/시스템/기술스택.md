# 기술 스택과 서버 신뢰 모델

> 정본: GDD-v1.0.md §1.1, §8 · 결정: [[ADR-029-godot4-csharp-이관]] · [[ADR-030-데스크톱-전용-배포]] · [[ADR-008-기술스택-웹-파이어베이스]](서버)

## 클라이언트 — Godot 4 + C#(.NET 8)

- 전투 규칙은 **Godot 무의존 클래스 라이브러리**(`engine/`)로 분리 — 렌더러 교체 가능성과 서버 리플레이 검증의 전제인 시드 결정성을 위해서다. Unity 배제
- **C# 인 이유**: 밸런스 도구(`sim/` 시뮬레이터 · `engine.tests/`)가 엔진과 같은 언어여야 살아남는다. GDScript 로 쓰면 시뮬을 버리거나 엔진을 두 벌 유지해야 하고, 후자는 규칙 드리프트를 부른다 ([[ADR-025-전투연산-순수모듈-분리]]·[[ADR-029-godot4-csharp-이관]])
- **배포: 데스크톱 전용** — macOS·Windows·Linux. **웹 내보내기는 Godot 4 + C# 이 지원하지 않는다** — C# 을 택한 대가다. 공유는 URL 이 아니라 실행 파일 전달이다
- 구 TS 스택(`packages/*`·`ui/game/*`)은 Godot 이 프롤로그·도감·업적·설정을 갖추고 밸런스 라운드 2가 끝날 때까지 **동결 상태로 병존**한다 — 새 기능은 Godot 에만 넣는다

| 프로젝트 | 역할 |
|---|---|
| `engine/` | 전투·런 규칙. Godot·fs·network 무의존 |
| `data/` | YAML 로더 (cards·enemies) |
| `sim/` | 시뮬레이터 CLI (밸런스 A/B) |
| `engine.tests/` | xUnit |
| `game/` | Godot 클라이언트 |

## 서버 — Firebase

| 구성 | 용도 |
|---|---|
| Firebase Auth | **구글 로그인** (Layer 3 진입점) |
| Firestore | boss_reviews, epitaphs(유언), votes, settlements, ugc_cards 등 컬렉션 |
| Cloud Functions | 서버측 검증(클램프·Tier 재계산), LLM 프록시, 정산 배치, 리플레이 검증 |
| Cloud Scheduler | 매시 슬롯 score 재계산, 일일 배당 정산(04:00) |

- 보안 규칙: 본인 문서만 쓰기, 읽기는 공개 컬렉션. Realtime DB·Storage 미사용
- 운영비 상한: 서버 ~$25/월 + LLM $50/월 = **월 약 10만원**
- 싱글 코어(Layer 1~2)는 네트워크 없이 100% 동작해야 한다 (검수 기준). 오프라인 폴백: 프리셋 리뷰 15종

## 서버 신뢰 모델 (Layer 3 착수 게이트)

클라 보고를 신뢰하지 않는다:

1. **클램프·재계산**: dmg_pct 0~100 클램프, cert_tier 서버 재계산, 이론 최대치 초과 거부
2. **작성권 서명 토큰**: 런 요약(시드·경로·로그 해시) 제출 → 휴리스틱 정합 검사 → 발급, TTL 10분
3. **리플레이 검증(v1.1)**: 시드+입력 로그 → Cloud Function 이 코어 규칙으로 결정적 리플레이. **상위 100 + 무작위 표본만** — 전수 검증·ML 이상 탐지는 하지 않는다 (1인 규모)
4. 스키마: boss_reviews 에 `crit_used`, `origin('defeat'|'victory')` 포함

## 로드맵 요약

Layer 1 MVP(3~4개월) → 1.5 풀 런(+2) → 2 경제(+1.5) → 3 비동기(+2) → 4 UGC(+1.5). 전체 출시 목표 12~15개월. 상세는 GDD §1.3.
