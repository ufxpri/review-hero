# ADR-025: 전투 연산을 순수 모듈로 분리하고 밸런스 상수를 외부 주입으로

- 상태: 확정 · 일자: 2026-08-07 · 출처: 사용자 결정
- 정본: `packages/core/src/rules.ts`(신설) · `packages/core/src/formula.ts`(신설)

## 맥락

`packages/core` 는 이미 UI 무의존이고 카드·적 데이터는 YAML 이 정본이다. 그러나 **밸런스
상수가 코드에 흩어져 있고, 계산이 상태 머신 안에 섞여 있다.**

| 위치 | 박혀 있는 값 |
|---|---|
| 모듈 상수 | 판정 배율·게이지·회복 |
| `Battle` 생성자 | 시작 의지 30, 필력 3 |
| 메서드 본문 | 초기 드로우 5, 손패 상한 8, 게이지 상한 10, 크리 고정 20, 바이럴 상한 12, 온보딩 배율 0.75/0.9, 퇴고 비용 1 |
| `ui/game/state.js` | **시작 의지 30 (엔진과 중복)** |

그 결과 ① 밸런스를 고치려면 코드 여러 곳을 찾아 고쳐야 하고 ② 계산만 따로 검증할 수
없으며(전투 상태를 만들어야 한다) ③ 시뮬레이터가 수치 A/B 를 비교할 방법이 없다.
방어·회복 축까지 들어오면서(ADR-023) 레버가 더 늘었다.

## 결정

### ① `rules.ts` — 밸런스 상수 단일 정본

모든 밸런스 수치를 `RulesConfig` 하나로 모으고 `DEFAULT_RULES` 를 기본값으로 둔다.
`Battle` 은 `cfg.rules` 로 **부분 오버라이드**를 받는다.

```ts
new Battle({ ...cfg, rules: { judge: { mult: { normal: 0.75 } } } })  // 일반 배율만 교체
```

- **코드에 남는 매직 넘버는 없다.** 규칙 수치는 전부 여기를 거친다.
- `ui/game/state.js` 의 시작 의지 중복을 제거하고 엔진 값을 참조한다.

### ② `formula.ts` — 순수 계산 함수

값을 받아 숫자를 돌려주는 함수만 둔다. `this` 없음, 상태 접근 없음, 부수효과 없음.

```ts
computeJudgement(card, targetTags, nullTags, isOrigin): Judgement
computeLikes(base, mult, vanityMult, fixedAdd, rules): number
computeGaugeDelta(judgement, inlineGauge, current, rules): number   // 클램프 반영 실증감
computeHeal(judgement, will, maxWill, rules): number
computeAbsorb(damage, defenses): { absorbed, remain, after }
```

`Battle` 은 **상태 머신 역할만** 남는다 — 손패·턴·효과 적용 순서를 관리하고, 수치는
전부 `formula` 에 위임한다.

### ③ 밸런싱은 파라미터 수정으로

밸런스 라운드는 코드가 아니라 **수치 표**를 고친다. 시뮬레이터가 `rules` 오버라이드를
받아 같은 시드에서 A/B 를 돌린다.

## 근거

- **검증이 싸진다.** 환산식 테스트에 전투 상태를 만들 필요가 없어진다 — 함수에 값만 넣는다.
- **드리프트가 구조적으로 막힌다.** previewSubmit 중복(ADR 없이 처리)과 `will: 30` 중복은
  같은 병의 증상이다. 계산 경로가 하나면 재현할 자리가 없다.
- **밸런스 라운드가 반복 가능해진다.** 수치 세트를 값으로 다룰 수 있으면 A/B·스윕이 가능하다.

## 기각한 대안

- **상수만 모으고 계산은 그대로 두기**: 싸지만 계산 검증이 여전히 전투 상태를 요구하고,
  `Battle` 이 1,200줄 갓 클래스로 남는다.
- **rules 를 YAML 로 외부화**: 코드 수정 없이 밸런싱이 가능해 가장 철저하다. 다만 지금은
  타입 안전과 IDE 지원을 잃는 대가가 더 크다. **`RulesConfig` 가 자리를 잡은 뒤 재검토** —
  구조가 같으므로 나중에 로더만 붙이면 된다.
- **효과 적용부(16분기)까지 이번에 분해**: 범위가 커져 방어·회복 작업과 충돌한다.
  Layer 1.5 착수 시점으로 미룬다.
