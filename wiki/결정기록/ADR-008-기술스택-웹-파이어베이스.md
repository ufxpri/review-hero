# ADR-008: 기술 스택 — 웹(TS) + 구글 로그인 + Firebase

- 상태: 확정 · 일자: 2026-07-30 · 출처: 클라이언트 = 설계 회의(실현성 #6), **서버 = 사용자 결정 (회의안 Supabase를 대체)**

## 맥락

회의는 서버로 Supabase(Postgres + Edge Function + pg_cron)를 추천했다. 사용자가 "웹 게임 + 구글 로그인 + Firebase 데이터 관리" 방향을 확정했다.

## 결정

- 클라이언트: TypeScript 웹 게임, 전투/런 로직은 UI 무의존 상태머신 패키지로 분리. 이식은 Tauri(1순위)/Godot, Unity 배제 (회의 결정 유지)
- 서버: **Firebase** — Auth(구글 로그인), Firestore, Cloud Functions(검증·LLM 프록시·정산), Cloud Scheduler(배치)

## 근거

- 1인 개발에서 Auth(구글 로그인)·클라이언트 SDK·배포가 가장 매끄러운 스택
- 이 게임의 서버 요구는 단순 CRUD + 배치 집계라 Postgres 관계형 기능이 필수는 아님

## Supabase 대비 유의점 (구현 시 확인)

- pg_cron 기반이던 "매시 슬롯 재계산·일일 정산"은 Cloud Scheduler + Functions로 치환
- votes의 (review_id, voter_id) 단일 PK는 Firestore 문서 ID 조합(`{reviewId}_{voterId}`)으로 유니크 보장
- 슬롯 score 정렬 같은 집계 쿼리는 Firestore가 약함 — 집계 결과를 문서로 미리 계산·저장(배치)하는 패턴 필수
- 리플레이 검증의 상태머신 재사용은 Cloud Functions(Node)와 TS 코어가 같은 언어라 오히려 유리
