# ADR-029: 클라이언트를 Godot 4 + C# 로 이관한다 — 웹 프로토타입 졸업

- 상태: 확정 · 일자: 2026-08-16 · 출처: 사용자 결정
- 대체: [[ADR-008-기술스택-웹-파이어베이스]]의 **클라이언트 부분**. 서버(Firebase) 결정은 유효
- 정본: `design/GDD-v1.0.md` §1.1 기술 스택

## 맥락

현재 클라이언트는 `ui/game/` 의 정적 HTML 10장(4,135줄)이다. `file://` 로 열리고, 화면
전환이 전체 새로고침(`location.href`)이며, 저장은 `localStorage` 뿐이다.

GDD §1.1은 이것을 처음부터 **「웹 프로토타입」**으로 규정하고 다음 칸을 비워 뒀다.
사용자가 지목한 불편은 넷이다.

| 불편 | 현행 원인 |
|---|---|
| 남한테 보여줄 수 없다 | 배포 대상이 없다 — 파일을 직접 열어야 한다 |
| 코드 구조가 수제비 같다 | 페이지마다 CSS·JS 를 자체 보유. `esc()`·카드 렌더가 5개 파일에 복제 |
| 저장이 기기에 갇혀 있다 | `localStorage` 단독 |
| 실제 게임처럼 안 보인다 | 화면 전환이 흰 화면 깜빡임. 사운드·씬 전환·트윈이 없다 |

## 결정

### ① 클라이언트 = Godot 4, 엔진 언어 = **C# (.NET 8)**

GDD §1.1은 「텍스트 중심이므로 게임 엔진·Canvas 불사용」으로 게임 엔진을 배제했으나,
그 판단은 **연출·씬 전환·사운드의 값을 낮게 본 것**이었다. 실제로 만들어 보니 네 번째
불편(「실제 게임처럼 안 보인다」)이 가장 크게 남았고, 이는 프레임워크 교체(Svelte 등)로는
해결되지 않는다. **배제 근거를 철회한다.**

### ② GDScript 가 아니라 C# 인 이유 — 밸런스 도구의 생존

`packages/core`(전투 엔진)·`packages/sim`(시뮬레이터)·테스트 65개는 **밸런스 라운드 1을
실제로 돌린 도구**다. 1,000판 × 3시드로 보스 승률 52%를 맞췄고, ADR-025가 만든
`--rule judge.mult.normal=0.9` 형태의 A/B 로 코드 수정 없이 수렴시켰다. **ADR-026이
남긴 밸런스 라운드 2(1막 자원 수지 202%)도 이 도구 없이는 돌아가지 않는다.**

- **GDScript 재작성** → 시뮬레이터가 사라진다. 남기려면 TS 엔진을 별도로 유지해야 하고,
  그러면 **엔진이 두 벌**이 되어 ADR-025가 없앤 규칙 드리프트가 훨씬 큰 규모로 재발한다.
- **C#** → 엔진·테스트·시뮬 CLI 가 전부 살아남는다. TS 와 C# 은 둘 다 정적 타입이라
  이관이 기계적이고, `rules.ts`/`formula.ts` 의 분리 구조(ADR-025)를 그대로 옮길 수 있다.

### ③ 구조

```
review-hero/
├ game/                  Godot 4 프로젝트 (씬·연출·입력)
│  ├ scenes/             타이틀·지도·전투·결과·명단
│  └ src/                Godot 측 C# (뷰·컨트롤러)
├ engine/                C# 클래스 라이브러리 — 전투 규칙 (Godot 무의존)
├ engine.tests/          xUnit — 현행 65개 이관
└ sim/                   C# 콘솔 — 시뮬레이터 CLI (--rule A/B 유지)
```

**`engine/` 은 Godot 을 참조하지 않는다.** 현행 `packages/core` 가 UI·fs·network·
`Date.now()`·`Math.random()` 을 금지한 제약을 그대로 승계한다 — 시드 주입 결정성이
서버 리플레이 검증(GDD §8)의 전제이기 때문이다.

### ④ 진행 순서 — 수직 쓸기

각 단계마다 **돌아가는 빌드**가 나오는 것을 우선한다. 중간에 멈춰도 플레이 가능한
산출물이 남는다.

| 차수 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 엔진·테스트·시뮬 C# 이관 | `dotnet test` 65개 통과 + **같은 시드에서 TS 시뮬과 같은 승률** |
| 2 | 타이틀 → 지도 → 전투 → 결과 (미술 없음) | 1막 한 판이 끝까지 굴러간다 |
| 3 | 드래그 앤 드롭·판정 연출·파티클 | 현행 웹 연출 수준 회복 |
| 4 | 운송장·메인 허브·명단 | 현행 기능 전량 이식 |
| 5 | 웹·데스크톱 배포 | URL 공유 + 실행 파일 |

### ⑤ 데이터 정본은 그대로 YAML

`design/cards-v2.0.yaml`·`enemies-v1.0.yaml` 이 계속 정본이다. C# 로더가 이것을 읽는다.
**게임 데이터를 Godot 리소스로 옮기지 않는다** — 밸런스 조정이 코드·에디터 밖에서
일어나야 한다는 원칙(ADR-025)은 언어가 바뀌어도 유지된다.

## 기각한 대안

- **Vite + Svelte SPA**: GDD §1.1이 원래 정한 길이고 이관 비용이 가장 싸다. 그러나
  네 번째 불편(연출·씬 전환)을 정면으로 해결하지 못한다.
- **현행 유지 + 정적 배포만**: 오늘 안에 끝나지만 나머지 세 불편이 그대로 남는다.
- **Godot + GDScript**: ②의 이유로 기각.
- **TS 엔진을 WASM 으로 감싸 Godot 에서 호출**: 데스크톱 내보내기에서 JS 런타임이 없어
  성립하지 않는다(`JavaScriptBridge` 는 웹 내보내기 전용).

## 남는 것 — Godot 이 해결하지 않는 것

**「저장이 기기에 갇혀 있다」는 Godot 으로 풀리지 않는다.** Godot 의 저장도 로컬 파일이다.
계정·클라우드 저장은 백엔드가 필요하며, 정본은 여전히 Firebase(ADR-008 서버 부분)다.
GDD §1.2상 Layer 3이므로 이번 이관과 분리해 진행한다.
