# ADR-030: 배포는 데스크톱 전용 — 웹 배포를 폐기한다

- 상태: 확정 · 일자: 2026-08-16 · 출처: 사용자 결정
- 개정: [[ADR-029-godot4-csharp-이관]] ④의 5차 「웹·데스크톱 배포」 중 **웹 부분 폐기**
- 정본: `design/GDD-v1.0.md` §1.1

## 맥락

ADR-029로 클라이언트를 Godot 4 + C#으로 옮기면서, 엔진 언어를 GDScript가 아닌 C#으로
택했다. 근거는 **밸런스 도구(시뮬레이터·테스트 65개)의 생존**이었고 실제로 살아남았다.

그런데 5차 착수 시점에 Godot이 웹 내보내기를 직접 거부했다.

> Exporting to Web is currently not supported in Godot 4 when using C#/.NET.
> Use Godot 3 to target Web with C#/Mono instead.

**C#을 택한 순간 웹 배포가 닫혀 있었다.** ADR-029는 이 대가를 적지 않았다 — 판단 근거가
불완전했고, 그 누락을 여기 기록한다.

사용자가 꼽은 네 가지 불편 중 「남한테 보여줄 수 없다」가 이 제약에 직접 걸린다.

## 결정

**배포는 데스크톱 전용으로 간다. 웹 배포를 폐기한다.**

- 대상: macOS · Windows · Linux
- 공유는 URL이 아니라 **실행 파일 전달**이다. 폰에서 열어보는 경로는 없다

### 기각한 대안

- **웹판(`ui/game/` HTML)을 공유용으로 병존**: 기존 자산을 그대로 쓰므로 가장 싸고,
  링크 공유가 즉시 열린다. 그러나 **클라이언트가 두 벌**이 되어 장기적으로 갈라진다 —
  지금은 두 엔진이 바이트 단위로 같지만(ADR-029 검증), 한쪽만 고치는 순간 무너진다.
  ADR-025가 없앤 규칙 드리프트를 클라이언트 층위에서 되살리는 셈이다.
- **엔진을 GDScript로 재작성**: 웹이 열리지만 시뮬레이터와 테스트 65개를 잃는다.
  ADR-029에서 이미 기각했고 근거는 그대로 유효하다 — 밸런스 라운드 2가 아직 남아 있다.
- **Godot 3으로 내려가기**: 웹 + C#이 되지만 Godot 4의 렌더러·타입·에디터를 포기한다.

## 구 웹 스택(`ui/game/`·`packages/*`)의 처리

**당장 지우지 않는다.** 이유 둘:

1. **아직 Godot에 없는 것이 있다** — 프롤로그 15슬라이드(가장 손이 많이 간 자산),
   만물대장 도감, 등재 기록(업적), 계정·설정 화면.
2. **TS 엔진은 이관 검증의 대조군이다.** 밸런스 라운드 2에서 수치를 바꿀 때
   양쪽이 같은 결과를 내는지가 회귀 검사로 쓰인다.

**폐기 조건**: Godot이 위 목록을 다 갖고, 밸런스 라운드 2가 끝나면 그때 판단한다.
그전까지 `packages/*`는 유지하되 **새 기능을 웹판에 추가하지 않는다** — 기능은
Godot에만 넣고 웹판은 동결한다. 두 벌을 나란히 키우는 것이 가장 나쁘다.

## 남은 위험 — 코드 서명

현재 빌드는 ad-hoc 서명이라 **로컬 실행·내부 배포까지만** 담보된다.
`codesign --verify --strict`를 통과하지 못하고, 받는 사람은 macOS의 「확인되지 않은
개발자」 경고를 수동으로 우회해야 한다.

정식 배포에는 Apple Developer ID(연 $99)와 공증(notarization)이 필요하다.
Windows도 SmartScreen 경고를 없애려면 코드 서명 인증서가 필요하다.
**스팀 출시 시점의 과제로 남긴다** — 스팀은 자체 배포 경로가 있어 서명 요구가 다르다.
