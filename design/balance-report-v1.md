# 밸런스 리포트 v1 — 시뮬레이터 실측 검증

- 작성: 밸런스 실험 담당 (2026-07-31)
- 대상: GDD-v1.0.md §3.1(전투 길이 기준선) / §3.4(게이지 경제) / §3.5(크리티컬 가치) / §3.8·§11(TBD R11: B01 의지 48 하향)
- 도구: `packages/sim` 시뮬레이터 — 감사 18건(수정 16/기각 2) 반영판. `tsc --noEmit`·`npm test` 31/31 통과 상태에서 실험.
- 지위: **본 문서는 실측 보고·제안이며 정본이 아니다.** GDD 수치는 변경하지 않았다(§7 제안만 기재).

## 0. 공통 설정·해석 규칙

- 전 실험 **seed 42 고정, 설정당 2,500판**(승률 ±2%p 판별용 최소 런 수 가이드 충족). 승률은 Wilson 95% CI 병기.
- 전투 길이 대조는 **승리 평균 턴(avg_wins)** 사용 — 패배(사망 절단)·시간초과 혼합 오염 방지(감사 #14).
- 게이지 지표는 `judgement_net/턴`(§3.4 이론치와 동일 정의: 판정 유래 raw 순증, 클램프 전) 기준. `applied_gain`(클램프 후, X08 포함)은 참고 병기.
- 판정 비율은 **의도(attempted, 정책 목표 롤) vs 실현(achieved, 엔진 판정)** 을 구분한다(감사 #10). §3.4 이론치의 전제(적중 50/75/30%)는 **의도** 에 해당한다.
- 교착 패배(리뷰 제출 0회 — 접두 없는 손패 고착, §3.1 설계 질의·에스컬레이션 중)는 정책 무관 강제 패배로, 전 매치업에서 동일 시드당 동일하게 발생(E0x 42판=1.7%, B01 boss1 덱 51판=2.0%). 본문 승률은 교착 포함 값이다.

## 1. 실험 1 — 전투 길이 (기준선: 일반 2~4 / 정예 5~6 / 보스 8~10턴, §3.1)

재현: `npx tsx packages/sim/src/cli.ts --enemy {E01..E05} --policy standard --runs 2500 --seed 42 --json`
(B01: `--enemy B01 --deck-preset boss1` 추가)

| 적 | 티어 | 승리 평균 턴 | 전체 평균 | 기준선 | 판정 |
|---|---|---|---|---|---|
| E01 고블린 잡상인 | 일반 | **2.12** | 2.30 | 2~4 | **통과** |
| E02 오크 중량 전사 | 정예 | **3.82** | 4.03 | 5~6 | **미달** |
| E03 엘프 이펙트 마법사 | 정예 | **2.81** | 3.16 | 5~6 | **미달** |
| E04 야매 배송 도적 | 정예 | **3.69** | 3.89 | 5~6 | **미달** |
| E05 나르시시스트 기사 | 정예 | **3.20** | 3.45 | 5~6 | **미달** |
| B01 답글 없는 사장 (boss1 덱) | 보스 | **6.11** | 6.38 | 8~10 | **미달** |

- **정예 4종 전원이 기준선을 1.2~2.8턴 미달** — 플레이어 화력(기준 턴당 8~12) 대비 정예 의지 16~24가 얕다. 크리가 "정예 이벤트"가 될 시간이 없다(정예 크리 발동 0.00~0.03회, §2 참조).
- **B01은 8~10턴이 구조적으로 불가능**: 턴 분포 상한이 7턴이다(2,500판 중 7턴 초과 0판). B01 사이클(계약 갱신 베기 8 + 야근 강요 4 + 답글 0)의 누적 피해가 7턴째 32로 플레이어 의지 30을 초과 — **7턴 사망 벽**. phase2(+3) 진입 시 벽은 더 당겨진다. 기준선 8~10턴은 플레이어 의지 30·B01 화력 현행 수치와 양립 불가(§7 제안 5).

## 2. 실험 2 — 게이지 경제 (B01 × 정책 3종, §3.4)

재현: `npx tsx packages/sim/src/cli.ts --enemy B01 --policy {standard|skilled|reckless} --runs 2500 --seed 42 --deck-preset boss1 --json`

| 정책 | 크리 발동(목표) | 도달(가능) | 판정 순증/턴 (이론) | 실반영 획득/턴 | 팩트 실현(의도) | 폴백률 | 판정 |
|---|---|---|---|---|---|---|---|
| standard | **0.48회** (7턴째 1회) | 0.53 | **+0.84** (+1.44) | +1.35 | 25.5% (50.2%) | 42.3% | **미달** |
| skilled | **0.72회** (2회) | 0.78 | **+1.26** (+2.8) | +1.75 | 37.8% (75.3%) | 47.1% | **미달** |
| reckless | **0.39회** (0회) | 0.49 | **+0.76** (+0.2) | +1.29 | 23.3% (—) | — | **초과** |

- **병목은 게이지 계수가 아니라 손패 가용성**: 의도 적중률은 §3.4 전제와 일치(50.2/75.3%)하나, 목표 접두 부재 폴백이 42~47%라 실현 적중이 23~38%로 압착된다. 그 결과 **standard(25.5%)와 reckless(23.3%)의 실현 팩트율 차이가 2.2%p** — 숙련도 변별이 손패 추첨에 씻겨나간다. 판정 횟수도 1.67~1.70회/턴으로 이론 전제(1.8~2.0회/턴)에 소폭 미달.
- 헛소리 실현율은 0~1.1%로 이론 전제(5~25%) 대비 극소 — 헛소리 접두가 손패에 없으면 일반으로 폴백하기 때문. reckless의 "게이지 0회" 목표는 이 구조에서 성립하지 않는다.
- **1순위 레버(팩트 적중 +2→+3) 실측** (core/battle.ts 508행 임시 패치 → 시뮬 → 원복, 동일 명령):

| 정책 | 크리 발동 +2 → +3 | 승률 +2 → +3 |
|---|---|---|
| standard | 0.48 → **0.73** | 59.0% → 72.8% |
| skilled | 0.72 → **0.86** | 82.0% → 84.7% |
| reckless | 0.39 → **0.62** | 48.7% → 60.9% |

레버 +3은 standard를 목표(1회)에 근접시키지만 **reckless 초과를 함께 악화**시킨다(0.39→0.62). 정책 변별 회복 없이는 레버 단독으로 목표 3종을 동시 충족할 수 없다(§7 제안 1·2).

## 3. 실험 3 — B01 의지 60 vs 48 (TBD R11)

재현: 위 명령에 `--will 48` 추가(이번 실험을 위해 CLI에 오버라이드 플래그 신설 — YAML 정본 불변).

| 정책 | 승률 60 → 48 | 승리 턴 60 → 48 | 크리 60 → 48 |
|---|---|---|---|
| standard | 59.0% [57.1~60.9] → **46.7%** [44.7~48.6] | 6.11 → 5.30 | 0.48 → 0.25 |
| skilled | 82.0% → **76.1%** | 5.47 → 4.72 | 0.72 → 0.48 |
| reckless | 48.7% → **42.9%** | 6.25 → 5.63 | 0.39 → 0.21 |

- **역설: 의지 하향이 전 정책 승률을 5.8~12.3%p 떨어뜨린다.** 원인은 phase2 트리거 "의지 30 이하"가 절대값 고정이라, 의지 48에서는 **18딜 만에 phase2(+3 공격)** 에 진입 — 사망 벽이 7턴→5턴으로 당겨진다(턴 분포 최빈값 7→5턴).
- 대조 시뮬(phase2 트리거 30→24 비례 동반 하향, 부록 A 스크립트): standard **46.7%→66.6%**, skilled 76.1%→84.9% — 하향 의도(Layer 1.5 중간 배치용 완화)가 회복된다.
- **판정: 현행 데이터 그대로의 48 하향은 R11 재시뮬 불통과. phase2 트리거 동반 하향(비례 24)을 조건으로 통과**(§7 제안 3).

## 4. 실험 4 — 성향별 크리 가치 (B01전, §3.5 기대 16~24딜 상당)

(CRN 시드 분기로 성향 간 크리 발동 수가 사실상 동일 — 발동 분포 차이 ≤2판 — 승률 차는 순수하게 크리 효과 차이다.)

| 성향 (크리) | standard 승률 | skilled 승률 | 승리 턴(std) | 판정 |
|---|---|---|---|---|
| 팩트 폭격기 (고정 20딜) | **59.0%** | **82.0%** | 6.11 | **통과** (20딜 = 기대 구간 정중앙) |
| 힙스터 평론가 (공격 −50%) | 42.5% | 68.9% | 6.80 | **미달*** (B01 한정 — 답글 최우선 반박 = 설계된 카운터) |

- 크리가 발동한 판(약 48%)만 조건부로 보면 격차는 표의 약 2배다. 팩트 폭격기 대비 다른 3성향은 승률 −13~−24%p 상당으로, **16~24딜 등가에 수렴하지 않는다.**

## 7. GDD 수치 변경 제안 (제안만 — 정본 미수정)

우선순위순. 1번이 GDD §3.4 지정 1순위 레버다.

1. **팩트 적중 게이지 +2 → +3** (§3.4): standard 크리 0.48→0.73회로 목표(1회) 근접. 단독 채택 시 reckless 0.62회로 초과 악화 — **제안 2와 묶음 채택 권장**.
2. **정예 의지 상향** (enemies YAML: E02 24→30, E03 18→24, E04 16→22, E05 22→28 안): 정예 전투를 5~6턴으로 끌어올려 (a) 정예에서 크리가 실제 이벤트가 되게 하고 (b) reckless의 낭비 턴이 누적 피해로 처벌되게 한다. 게이지 감소 카드가 덱에 없는 현 1막에서 억지 처벌은 게이지가 아니라 **전투 길이**로만 구현 가능하다.
3. **B01 phase2 트리거 "의지 30 이하" → "의지 50% 이하"** (§3.8·YAML): R11의 48 하향을 실제 완화로 만들기 위한 필요조건(실측 46.7%→66.6%). 의지 60 현행에서는 30=50%라 무변화 — 지금 바꿔도 MVP 무영향.
4. **보스 전투 길이 기준선 8~10턴 재검토** (§3.1): 플레이어 의지 30·B01 화력 현행에서 7턴 사망 벽으로 도달 불가. (a) 기준선을 6~7턴으로 현실화하거나 (b) 플레이어 의지 30→36 또는 B01 야근 강요 4→3 하향으로 벽을 9턴대로 이동. (a)가 저비용.
5. **바이럴 앞잡이 크리 하한 보강** (§3.5): 버프 0개일 때 가치 0인 조건부 크리 — "버프 2배, 버프 없으면 S13 상당(+3) 버프 1개 즉시 부착" 류의 바닥 보장 검토. 4성향 중 유일하게 전 정책 최하위.
6. **프로 불편러 기절의 보스 가치** (§3.5): B01 기믹(답글)이 기절 무시 + 경직 내성으로 실질 이득이 공격 1회 회피에 그침 — 갈취 골드 상향(보스 25→35G)보다는 "기절 대신 다음 공격 −50%" 등 피해 등가 재설계 검토.
7. (수치 아님 — 기존 에스컬레이션 재확인) 교착 패배 1.7~2.0%는 §3.1 손패 안전장치 결정 전까지 전 승률에 하방 편향으로 남는다. 보스 도달 기대 덱 정본 정의도 실험 3·5 판정의 전제다.

## 부록 A — 재현 절차 보충

- phase2 대조 실험 스크립트(스크래치패드 실행본과 동일):

```ts
// npx tsx exp3_phase2.ts (cwd: 저장소 루트) — B01 will=48에서 phase2.triggerWill 30 vs 24 대조
import { Battle, mulberry32 } from './packages/core/src/index.ts';
import { loadAll } from './packages/sim/src/data.ts';
import { playTurn, type PolicyName } from './packages/sim/src/policies.ts';
const data = loadAll();
const base = data.enemies.get('B01')!;
const deck = [...data.startingDeck, 'P11', 'P15', 'S02'];
function run(will: number, trigger: number, policy: PolicyName, runs = 2500, seed = 42) {
  const enemy = { ...base, will, phase2: { ...base.phase2!, triggerWill: trigger } };
  const root = mulberry32(seed);
  let wins = 0;
  for (let r = 0; r < runs; r++) {
    const s = Math.floor(root() * 0xffffffff);
    const b = new Battle({ cards: data.cards, enemy, deck, rng: mulberry32(s), layer: 1 });
    const prng = mulberry32((s ^ 0x9e3779b9) >>> 0);
    let g = 200;
    while (!b.state.result && g-- > 0) playTurn(b, data.cards, policy, prng);
    if (b.state.result === 'win') wins++;
  }
  console.log(will, trigger, policy, (wins / runs * 100).toFixed(1) + '%');
}
for (const p of ['standard', 'skilled'] as PolicyName[]) { run(48, 30, p); run(48, 24, p); }
```
